# Cobblestone

Консольное приложение на C++23 для управления базой знаний и задачами. Поддерживает вложенность заметок (деревья), теги, поиск и отмену действий (Undo/Redo). Данные асинхронно сохраняются локально в формате Markdown + YAML.

## Инструкция по сборке и запуску

#### **Способ 1: Docker (Рекомендуемый)**

Сборка и запуск в изолированной среде. Заметки будут сохраняться в папку `my_notes/`.

```bash
docker compose build
docker compose run --rm cobblestone
```

#### **Способ 2: Ручная сборка**

Требуется компилятор с поддержкой C++23.

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build

# Запуск приложения:
./build/cli/cobblestone
# Запуск тестов:
cd build && ctest --output-on-failure
```

## Архитектура и проектирование

Приложение разделено на 4 независимых слоя (Clean Architecture):
1. **`core`**: Доменная логика и базовые типы. Не имеет внешних зависимостей.
2. **`app`**: Движок приложения (`LifeEngine`) и бизнес-сценарии.
3. **`infra`**: Инфраструктура (парсинг YAML и файловое хранилище).
4. **`cli`**: Консольный интерфейс.

### Принципы SOLID и GRASP

* **Single Responsibility Principle** Консольный ввод/вывод (`ConsoleApp`), бизнес-логика (`LifeEngine`) и сохранение файлов (`MarkdownStorage`) строго разделены.
* **Open/Close Principle** Новые команды (например, архивация) добавляются созданием новых классов интерфейса `ICommand`, без из  менения ядра.
* **Dependency Inversion Principle** Логика не зависит от файловой системы. `LifeEngine` работает с абстрактным `IStorage`, что позволяет использовать Mock-объекты в тестах.
* **Low Coupling / High Cohesion:** Слой `core` сильно связен (содержит только правила предметной области) и отвязан от любых деталей реализации.

### Паттерны GoF
1. **Command (Команда):** Действия пользователя инкапсулируются в объекты. Это позволило реализовать надежные очереди `Undo` и `Redo`.

2. **Memento (Снимок):** При редактировании контента создается "снимок" сущности. Если при редактировании происходит сбой, состояние безопасно восстанавливается.

3. **Facade (Фасад):** Класс `LifeEngine` скрывает от UI сложную работу с графом (реестром), историей команд и асинхронным хранилищем.

## Тестирование (GTest + GMock)

Тесты находятся в папке `tests/` и покрывают позитивные, негативные и граничные сценарии.

**Краткий тест-план:**
* **Модульные тесты (Unit):** 
  * Проверка валидации строк (пустые заголовки, невидимые символы, спецсимволы в тегах) через параметризованные тесты (`TEST_P`).
  * Проверка графового реестра (защита от циклических зависимостей дерева).
  * Обработка сломанных файлов парсером (отсутствие полей, кривой YAML).
* **Интеграционные тесты и Mocks:**
  * С помощью `StrictMock` хранилище полностью изолировано.
  * **Failure Injection:** Имитация ошибки сохранения на диск (`SystemError`). Проверяется, что программа не падает, а заметка сохраняет статус "несохраненной" (Dirty).
  * **Проверка истории:** Отмена каскадного удаления ветки дерева (дочерние заметки корректно возвращаются к родителю).
